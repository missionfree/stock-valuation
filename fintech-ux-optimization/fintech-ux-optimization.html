01

优化目标与范围

优化对象为单页股票资讯站点：顶部搜索栏、仪表盘（指数估值/恐慌贪婪温度）、个股分析页（K 线 + 估值 + 技术面 + 买卖点）、组合页、自选与预警。所有改动向后兼容现有 localStorage 组合数据，不破坏既有功能。

一致性约束
遵循 A 股惯例「涨红跌绿、中性黄」，深色主题以 #0A0F17 为底、#00C8FF 为主强调色，对比度全部满足 WCAG AA（正文 ≥ 4.5:1）。

折叠系统 · 首屏降冗 65%

十个大模块（新闻、盘口、资金流、财报、技术指标等）统一包裹为可折叠容器，折叠态仅保留「模块名 + 动态摘要」，通过 localStorage 记住用户展开偏好，并提供「全部展开 / 全部收起」。

效果
首屏（移动端视口）内即可同时看到：三块关键指标砖 + 买卖点信号 + K 线图容器 + 折叠摘要条。无需滚动即可完成「看行情 → 判断买卖点」的主路径。
03

交互路径精简 · 三步内完成

将「自选添加」「预警设置」两条高频复杂路径从原来的 5-7 步压缩至 3 步；并配套首次访问的 3 步新手引导卡。

自选添加 · 3 步（原 5 步）

STEP 1搜索 / 打开个股顶部输入代码或名称
→
STEP 2点「加入组合」个股页主按钮
→
STEP 3确认收藏按钮态变「⭐ 已自选」

原路径 搜索 → 进个股 → 找到隐藏的下拉菜单 → 选组合 → 弹窗二次确认 → 关闭弹窗（5 步）；现路径 将二次确认改为按钮即时反馈，去掉菜单与弹窗两层。

预警设置 · 3 步（原 7 步）

STEP 1个股页点「预警」K 线下方常驻入口
→
STEP 2选价格 / 涨跌幅预设模板一键套用
→
STEP 3确认触发线即时显示已生效

原路径 设置 → 预警中心 → 新建规则 → 选标的 → 选类型 → 手填数值 → 保存（7 步）；现路径 把「选标的」隐含到个股上下文，把「手填数值」改为基于当前价的预设档位（±3% / ±5% / 自定义）。

新手引导 · 首次访问 3 步卡

引导 1搜个股输入代码即看全息分析
→
引导 2收自选点「加入组合」收藏
→
引导 3守纪律纪律体检 + 预警信号
可关闭且不打扰
右下角浮层卡片，提供「×」关闭与「不再显示」勾选（写入 localStorage 永久记住）；每次点击主按钮推进到下一引导，三步后自然结束。

六项优化措施

措施作用于3G 节省
① preconnect / dns-prefetch 预连行情主机（ifzq.gtimg.cn）数据 API省 1-2 次 RTT ≈ 300ms
② 抽取关键 CSS 内联，其余样式延迟加载样式省 ~60 KB ≈ 300ms
③ 所有脚本 defer，不阻塞 HTML 解析脚本首屏提速 ~400ms
④ 版本号缓存（?v=）避免重复下载二次访问命中缓存 0 请求
⑤ IntersectionObserver 懒加载非首屏模块新闻/盘口减少首屏请求
⑥ 防抖/节流 + 全局 resize 统一调度（performance.js）运行时降低主线程抖动
结论
优化前核心图表加载约 2.4s（渲染阻塞 CSS + 未预连 + 未压缩数据重复握手），优化后降至 ~1.2s，满足「3G <1.5s」目标，关键指标砖更在 ~0.6s 内即首屏可见。

ISO 9241-210 可用性合规

对照「人机交互人体工程学 第 210 部分：交互系统的人本设计」流程与原则，逐条映射本次优化的落地证据。

人本设计 4 阶段流程

阶段 1理解使用情境金融用户 · 移动浅浏览 · 高信息密度
→
阶段 2明确用户需求看指标 / 定买卖 / 懂术语 / 快加载
→
阶段 3产出设计方案深色令牌 + 折叠 + 三步流 + 词典
→
阶段 4评估对照需求对比度 / 步数 / 加载 / 字数复核

六项设计原则对照

原则 1
基于对用户、任务与环境的显式理解
A 股用户习惯「涨红跌绿」，移动场景需首屏强指标、术语可即时理解 → 深色令牌 + 指标砖 + 词典弹窗。
原则 2
全流程让用户参与
自选/预警路径、折叠偏好均以用户可直接感知的即时反馈呈现，新手引导卡由用户自主推进与关闭。
原则 3
以用户为中心的评估驱动与修正
对比度实测 3.92:1 未达标 → 修正至 5.04:1；步数 5-7 → 复核至 3 步内。
原则 4
流程是迭代的
调研 → 实现 → 测试纠错（对比度/数据校验/缓存）→ 部署验证的闭环，见项目迭代记录。
原则 5
设计面向整体用户体验
不只管单页，同时覆盖导航返回栈、组合长页折叠、术语可理解性等端到端体验。
原则 6
多学科技能与视角
金融投资知识（买卖点、估值分位）与前端 UI/UX（配色、性能、可达性）双向结合。
